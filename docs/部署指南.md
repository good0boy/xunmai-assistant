# 部署指南

面向「**上传文件到服务器 → docker compose 部署**」的方式（服务器不出外网或出网受限）。
目标：服务器上零外网依赖也能跑起来。

---

## 1. 硬件与依赖

| 项 | 建议 | 说明 |
|---|---|---|
| CPU | 4 核以上 | ONNX 推理 + Qdrant |
| 内存 | 8 GB 以上 | embedding 模型常驻约 400MB，索引全量载入内存 |
| 磁盘 | 30 GB 以上 | 索引 20MB + 模型 92MB + 上传图片 + 日志 |
| Docker | 20.10+ 与 docker compose v2 | 服务器上唯一的前置软件 |
| LLM 网关 | 服务器可达 | `.env` 里 `LLM_BASE_URL` 指向内网网关 |

**embedding 模型已内置**：`backend/kb_src/models/` 里带了一份完整的 HuggingFace
缓存布局（`BAAI/bge-small-zh-v1.5` 的 ONNX 优化版，90.4MB）。
应用启动时会把它拷进可写的缓存目录（`/data/models`），所以**服务器完全不出网
也能跑 dense 检索**。详见 `backend/kb_src/models/README.md`。

## 2. 本地准备部署包

### 2.1 打包项目文件

在本地项目根目录执行（Windows 用压缩软件打包，内容一样）：

```bash
tar -czf xunmai-deploy.tar.gz \
  --exclude=.git --exclude=.workbuddy --exclude=.env \
  --exclude=node_modules --exclude=frontend/dist \
  --exclude=data/models --exclude=data/reports \
  --exclude=dist_release --exclude=backend/_local \
  backend frontend docs docker-compose.yml Makefile .env.example README.md
```

包内自带三样关键东西：

| 内容 | 作用 |
|---|---|
| `backend/kb_src/models/`（92MB） | embedding 模型，服务器不出网也能跑语义检索 |
| `backend/kb_src/nihaixia/` + `external/` | 知识库语料，建索引用 |
| `.env.example` | 环境配置模板 |

### 2.2 导出 Docker 镜像（服务器拉不动 Docker Hub 时必做）

构建需要 4 个基础镜像。服务器能拉 Docker Hub 就跳过这步；
拉不动就在**本地**导出成 tar，随部署包一起上传：

```bash
docker pull python:3.12-slim
docker pull node:22-alpine
docker pull nginx:1.27-alpine
docker pull qdrant/qdrant:v1.12.4

docker save python:3.12-slim node:22-alpine nginx:1.27-alpine qdrant/qdrant:v1.12.4 \
  -o xunmai-images.tar
```

> 导出约 700MB。服务器上 `docker load -i xunmai-images.tar` 导入，
> 之后 `docker compose build` / `up` 就不再访问 Docker Hub。

### 2.3 可选：直接上传索引（省 9 分钟建库）

本地已经建好索引的话，把 `data/qdrant/` 打个包一起上传，服务器上解到同一路径，
即可跳过建库步骤（Qdrant 的 storage 目录跨平台通用）：

```bash
tar -czf xunmai-qdrant-index.tar.gz -C data qdrant
```

不上传也行，服务器上重建（见 3.4，约 9 分钟，不需要 LLM 参与）。

### 2.4 路线判定

| 服务器网络状况 | 走哪条 |
|---|---|
| 能访问国内站点（阿里云镜像、npmmirror） | **路线 A**：上传部署包 → compose build（构建全程走国内源） |
| 完全无外网 | **路线 B**：额外完成 2.2 的镜像导出上传；在**本地**构建好镜像后 save 上传（见 3.5） |

## 3. 服务器上部署

以下命令默认在解压后的项目根目录执行。

### 3.1 导入基础镜像（走了 2.2 的话）

```bash
docker load -i xunmai-images.tar
docker images | grep -E "python|node|nginx|qdrant"
```

### 3.2 准备配置

```bash
cp .env.example .env
vi .env
```

`.env` 必须检查的项：

```bash
# ---- LLM 网关（必填）：必须是服务器自己能访问到的地址 ----
LLM_BASE_URL=http://内网网关IP:4000
LLM_API_KEY=sk-xxxx
LLM_MODEL=模型名

# ---- 访问控制：默认留空 = 所有人可用；要限制再填 ----
APP_PASSCODE=
ADMIN_TOKEN=

# ---- 前端地址：写用户浏览器实际访问的地址（服务器 IP 或域名）----
CORS_ORIGINS=http://服务器IP:8090
```

> 容器内路径（KB_ROOT / FASTEMBED_CACHE_PATH / DB_URL 等）由
> `docker-compose.yml` 的 environment 显式覆盖，`.env` 里的相对路径写法
> 在容器内不会生效，不用改。

### 3.3 构建、启动、建索引

**路线 A（服务器能出国内网）**——构建时 pip/apt/npm 全部走阿里源（已内置在
Dockerfile 里，不需要额外配置）：

```bash
docker compose build          # 构建前后端镜像（国内源）
docker compose up -d          # 起 qdrant + backend + frontend
```

**路线 B（完全无外网）**——在本地构建好镜像，导出上传：

```bash
# 本地执行
docker compose build
docker save xunmai-backend xunmai-frontend -o xunmai-app-images.tar
# 上传后在服务器执行
docker load -i xunmai-app-images.tar
docker compose up -d          # 镜像已就位，up 不再触发构建
```

**建索引**（上传了 2.3 的索引包就跳过）：

```bash
tar -xzf xunmai-qdrant-index.tar.gz -C data/   # 解到 data/qdrant/
# 或者服务器上重建（约 9 分钟，本地 embedding，不需要 LLM）：
docker compose run --rm backend python -m scripts.build_index
```

### 3.4 验证

```bash
docker compose ps                                  # 三个容器都 Up
curl -s http://127.0.0.1:8000/api/v1/health        # kb_status=ready, dense_available=true
```

浏览器访问 `http://服务器IP:8090`。`dense_available: false` 表示 embedding
模型没加载——检查 `backend/kb_src/models/` 是否随包上传（启动日志找
「拷贝随包 embedding 模型」）。

### 3.5 本地开发（不用容器，附）

Windows / 直跑 Python 的开发方式：

```bash
docker compose up -d qdrant
cd backend && .venv/Scripts/python.exe -m scripts.build_index
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
# 前端另开终端：cd frontend && npm run dev（http://localhost:5173）
```

## 4. 数据卷与备份

| 路径 | 内容 | 是否需要备份 |
|---|---|---|
| `backend/kb_src/` | 语料 + 外部来源 + **embedding 模型** | 需随部署包带走（模型在里面） |
| `data/qdrant/` | 向量索引（三个集合，共约 1.2 万块） | 可重建，但重建要 9 分钟，建议备份 |
| `data/models/` | embedding 模型运行时缓存 | 不用备份，删了会从 `kb_src/models` 重新拷 |
| `data/app.db` | 会话、消息、引用、kb_meta | **必须备份**（用户历史） |
| `data/uploads/` | 用户上传的舌象/面色图片 | 建议备份 |
| `data/reports/` | 建库与评测报告 | 不重要 |

备份：

```bash
tar -czf xunmai-backup-$(date +%F).tar.gz data/app.db data/uploads data/qdrant
```

恢复时把文件放回原位即可（索引可选择一起恢复，或重新 `build_index`）。

**只补建某几组索引**：

```bash
docker compose run --rm backend python -m scripts.build_index --groups classics,judges
```

## 5. 反向代理（Nginx）

**SSE 必须关缓冲**，否则前端会退化成「等生成完一次性显示」：

```nginx
server {
    listen 80;
    server_name your.domain;

    location /api/v1/chat/stream {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Connection '';
        proxy_buffering off;          # 关键
        proxy_cache off;
        chunked_transfer_encoding on;
        proxy_read_timeout 300s;      # 生成可能超过 60s
        proxy_send_timeout 300s;
    }

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> 前端容器自带 nginx（宿主 8090 → 容器 80）只托管静态文件并反代 `/api` 到 backend，
> 不经过这层时无需额外配置；这节是给「再套一层外层 Nginx 做域名/HTTPS」的场景。

验证代理没缓冲：

```bash
curl -N --max-time 20 http://your.domain/api/v1/stream-probe
```

**逐条滚动出现 = 代理无缓冲**；7.5 秒后一次性全出来 = 缓冲没关掉。

## 6. 访问控制

**默认不启用鉴权，所有人可用**（`.env` 里两项都留空即可，本机/内网信任环境的推荐配置）。

要限制访问时才填（显式配置才拦）：

| 配置项 | 作用 | 谁用 |
|---|---|---|
| `APP_PASSCODE` | 入口口令，`X-App-Passcode` 头 | 最终用户，在登录框输入 |
| `ADMIN_TOKEN` | 接口令牌，`X-Admin-Token` 头 | 运维/脚本调用 |
| `RATE_LIMIT_PER_MIN` | 每 IP 每分钟请求上限（默认 20） | — |
| `DAILY_TOKEN_BUDGET` | 每日 token 预算（默认 200 万） | — |

`/api/v1/health` 与 `/api/v1/config` 永远公开，前端要靠它们判断是否弹登录框。

> 限流是**进程内**计数。多 worker 或多副本部署时，实际限额是配置值的倍数，
> 需要精确控制就在 Nginx 层加 `limit_req`。

## 7. 日常运维

```bash
make logs          # 看日志
make restart       # 重启
make eval          # 检索评测
make test          # 后端单测
cd frontend && npm test   # 前端单测
```

**日志里已带的分段耗时**（`chat done` 事件）：
`retrieval_ms` / `embed_ms` / `search_ms` / `rerank_ms` / `elapsed_ms`。
排障时先看这几个数就能分清是检索慢还是模型慢。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker compose build` 拉 python/node 镜像超时 | 服务器拉不动 Docker Hub | 走 2.2 + 3.1 的镜像离线导入 |
| build 时 pip/npm 装依赖失败 | 出不了国内网 | 确认 Dockerfile 已用阿里源（本版已内置）；完全无网走路线 B |
| 首页能开但点发送没反应 | 反代开了缓冲 | 见第 5 节，`proxy_buffering off` |
| `kb_status: stale` | 代码/词典变了但没重建索引 | `make kb` |
| `kb_status: missing` | 索引不存在 | 3.3 的建索引步骤 |
| `dense_available: false` | 随包模型没拷进缓存目录 | 看 `backend/kb_src/models/` 是否随包上传；启动日志找「拷贝随包 embedding 模型」 |
| 首字节很慢（>5s） | 首次检索在加载模型 | lifespan 已预热，若仍慢看 `embed_ms` |
| 401 | 凭据没带上 | 前端登录框；`/health` 与 `/config` 不需要凭据 |
| 启动日志报「随包模型拷贝失败」 | 缓存目录不可写 | 检查 `data/` 卷权限；不致命 |
